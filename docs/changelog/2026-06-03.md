#### Root cause: justETF API drift

justETF migrated its search endpoint from HTML-snippet arrays (handled by
`_parse_search_result`) to a Wicket/DataTables JSON API returning structured
dicts. The current `search_etfs()` implementation:

1. Calls `_get_counter()` which finds counter `"0"` (still present in page)
2. POSTs to `search.html?0` — but that URL is a GET-only HTML page, not the DataTables endpoint
3. Gets back HTML instead of JSON
4. `_parse_search_result()` receives dicts (not list items) → returns `None` for every record

The actual DataTables endpoint requires:
1. GET `/en/search.html` → extract `fetchCallbackUrl` from the config JSON in the HTML
2. POST to that Wicket URL with DataTables payload (`draw`, `start`, `length`, etc.)
3. Response is a JSON array of structured ETF objects with `isin`, `ticker`, `name`, `fundCurrency` directly

This is a **fixable** code issue, not a justETF data problem.

#### EUNL ISIN correction

The spec had `IE00F4030284` for EUNL.DE — this ISIN does not exist on justETF
(page returns a search redirect with no profile). The live API returns
`IE00B4L5Y983` (iShares Core MSCI World UCITS ETF USD Acc), which is the
correct ISIN for ticker `EUNL`. Spec must be corrected before Phase 2.

### What shipped

#### 1. Fixed `search_etfs()` — Wicket/DataTables API (justetf.py)

Replaced broken `_get_counter()` + HTML-snippet `_parse_search_result()` with the
correct Wicket/DataTables mechanism:

- New `_get_fetch_callback_url()`: GET `/en/search.html` → regex-extract
  `fetchCallbackUrl` from embedded JSON config → full absolute URL.
- Updated `search_etfs()`: POST to that URL with DataTables payload, receive
  structured JSON dicts, filter client-side by exact ticker match (uppercase).
- `_parse_search_result()` kept as deprecated fallback for `find_similar_etfs()`
  backward compat; now passes dict rows through directly.
- `_get_counter()` kept as backward-compatible alias returning query-string portion.

**Live gate: GO** — VWCE.DE→IE00BK5BQT80, VUSA.L→IE00B3XXRP09, EUNL.DE→IE00B4L5Y983.

#### 2. `compute_isin_confidence()` pure function (justetf.py)

Gate v2 (currency cross-check REMOVED — see design revision below):
- Normalises `ticker_root`: strip `.DE`/`.L`/`.SW`/`.AS`/`.MI`/`.PA`/`.MC`/`.F`/`.XD`, uppercase.
- Filters rows by exact ticker match.
- `distinct_isins == 1` → `high` (UCITS funds share one ISIN across exchanges).
- `distinct_isins >= 2` → `low` + candidates list (genuinely ambiguous).
- No match or None input → `none`.

#### 3. `resolve_isin_from_ticker()` (justetf.py)

Thin orchestrator: normalise → `search_etfs(root)` → `compute_isin_confidence()`. 1h cache.

#### 4. Endpoint `GET /etf/resolve-isin/{ticker}` (routers/justetf_routes.py)

- 15/min rate limit, no auth (consistent with other /etf/* routes).
- Returns `{ticker, isin, confidence, name, candidates}`.
- Never 5xx: degrades to `confidence=none` on any exception.
- 400 on empty or >20-char ticker.

### Design revision: currency cross-check removed

Original design had a `profile.fundCurrency == yf_currency` check as gate condition 2.
This is WRONG: justETF reports fund BASE currency (USD for EU UCITS ETFs), not the
exchange trading currency. All VWCE/VUSA/EUNL have `fundCurrency=USD` but trade in
EUR (.DE) or GBP (.L). The check would mis-reject every EU ETF. Removed.
Gate v2 relies solely on: exact ticker match + single distinct ISIN.
